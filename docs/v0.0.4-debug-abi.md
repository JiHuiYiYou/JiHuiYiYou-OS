## § 1 Goals + 5 原则 compliance

### 1.1 设计目标

`highlights-plain-language.md § 7` 提出 L1-L4 四层 debug 架构。本 spec 把 design intent 落地为具体 ABI:

- **L2 walkable error chain**: 当前 placeholder(`Err { code, prev, trace }`)→ § 5 ErrChain ABI 定长 + c-typedef
- **L3 KernelState enum + history**: 当前 undefined → § 6 KernelState + ring buffer 定长 layout
- **L4 Cap provenance**: 已有 `v0.0.1-capability.md § 5` jhyy-side struct 7 字段 → 本 spec 加 wire format + 三级标记(§ 4)+ DAG 增强(§ 7)
- **跨边界 LLM agent 拉取**: 当前无 spec → § 2 DebugEvent 统一 ABI + § 8 CodeGraph 联合自省定位

### 1.2 5 原则 compliance(per `v0.0.0-design.md § 2`)

| 原则 | 本 spec 怎么满足 |
|------|------------------|
| **可行且简单** | DebugEvent header 56B 定长(8 字节对齐,内嵌 SourceLoc 24B)+ 可变 payload 借鉴 D16 cap-offset pattern(16B header + 可变);Confidence enum 简单 3 值;ErrChain 是成熟 linked-list 模式(Linux errno chain / Rust error chain 验证) |
| **双线作战** | 不破现有 `Err / Cap / state / arena` 设计;只是 add-only 元数据层;DebugEvent 跟 syscall ABI 正交 |
| **寄生 Windows** | debug build / release strip pattern(per D14/D21 ProvenanceInfo side table);本 spec 沿用同一模式(KernelStateHistory / ErrChain 都 strip in release) |
| **Debug 在语言里** | DebugEvent 是 first-class(jhyy-side `DebugEvent` struct + `emit()` builtin);不是 gdb 风格 external protocol |
| **Kernel 不解决语言问题** | spec 是语言层 + wire format;kernel 只 expose ring buffer(NOT kernel 设计 language construct);Confidence 标记由 sema 填(per compiler),kernel 不知道 Confidence 是什么 |

## § 2 DebugEvent 统一 ABI(新)

### 2.1 设计动机

当前 OS 内部 introspection 信息分散在:
- `v0.0.1-capability.md § 5` ProvenanceInfo(side table)
- `v0.0.1-syscall-abi.md § 1.4.1` SysError
- (未定义)KernelState history

LLM agent 拿到任意一条 cap / error / state,需要 union 类型把它们统一。

**DebugEvent** = 统一 introspection 记录 wire format。

### 2.2 Header layout(56 字节定长,小端,amd64 自然对齐)

> **字段按对齐降序排列**(u64 → 24B struct → u32 → u8),这样只需 2B 尾部 padding 就满足全部自然对齐。
> **为什么必须自然对齐**:jhyy 无 `packed` / `repr(...)` 布局控制(lang-spec § 2.2:`struct` = "字段之和(对齐)"),且 3a-3n 全部 sprint 均未规划该特性 —— 紧凑布局在 jhyy 侧不可表达,故 wire-format 只能自然对齐。(per D41 review R1)

```c
// C-typedef(对应 jhyy-side 同样 struct)
typedef struct DebugEvent {
    uint64_t  timestamp_ns;   // 运行期基线 (CLOCK_MONOTONIC)
    uint64_t  payload_ptr;    // ptr to payload (relative to event header base)
    SourceLoc source_loc;     // 24 字节内嵌 (§ 2.3)
    uint32_t  event_type;     // DebugEventKind enum (§ 3)
    uint32_t  source_cid;     // CapId (0 = none,例如纯 ErrThrown 无 cap)
    uint32_t  payload_len;    // 可变 payload 字节数
    uint8_t   confidence;     // Confidence enum (§ 4)
    uint8_t   flags;          // reserved (must be 0)
    uint16_t  _pad;           // 2 字节尾部 padding (must be 0)
} DebugEvent;                // sizeof = 56 字节, alignof = 8
```

| 字段 | 偏移 | 大小 | 用途 |
|------|------|------|------|
| timestamp_ns | 0 | 8 | 运行期基线(CLOCK_MONOTONIC 等效,ns 精度) |
| payload_ptr | 8 | 8 | ptr to payload(可指向嵌套 DebugEvent 链表) |
| source_loc | 16 | 24 | 见 § 2.3 |
| event_type | 40 | 4 | DebugEventKind enum |
| source_cid | 44 | 4 | CapId(0 = no cap involved) |
| payload_len | 48 | 4 | 可变 payload 字节数 |
| confidence | 52 | 1 | Confidence enum(§ 4) |
| flags | 53 | 1 | reserved (must 0) |
| _pad | 54 | 2 | 尾部 padding (must 0) |

> 大小校验:末字段 `_pad` 偏移 54 + 2 = **56**,且每个字段满足 `offset % alignof(字段) == 0`(`timestamp_ns`/`payload_ptr` 8-aligned;`source_loc` @16 8-aligned,其内嵌 u64 `reserved` 亦然)。
>
> **修正记录(2026-08-12, D41 review R1)**:初稿声称 54B,三处自相矛盾 —— 字段尺寸和 = 54、偏移表实际跨度 = 56(42-43 有 2B 未记账)、而按初稿字段序真做自然对齐 = 64(`timestamp_ns: u64 @4` 未 8 对齐)。现按对齐降序重排,得 56B 且**无需任何显式内部 padding**。

### 2.3 SourceLoc 内嵌(24 字节)

```c
typedef struct SourceLoc {
    uint32_t file_offset;     // offset into debug file table(per build)
    uint32_t line;
    uint32_t column;
    uint64_t reserved;        // 8 字节 padding,future use (e.g. inline call depth)
} SourceLoc;                 // sizeof = 24 字节
```

### 2.4 Payload 序列化(tree → flat, 单向链表)

- **嵌套 DebugEvent**: payload 是另一个 DebugEvent(单向链表,tree→flat)
- **叶子**: `payload_len = 0`, `payload_ptr = 0`
- **嵌套**: `payload_ptr` 指向下一个 DebugEvent;`payload_len` = 后续总字节数(含递归)

例:`ErrThrown(outer)` 嵌套 `CapConstructed(inner)`:
```
[outer DebugEvent 56B]
   event_type = ErrThrown
   payload_len = 56
   payload_ptr → [inner DebugEvent 56B]
                   event_type = CapConstructed
                   payload_len = 0
                   payload_ptr = 0
```

### 2.5 Wire format 总原则

- **小端**(amd64 字节序;QBE 默认 emit 小端)
- **8 字节对齐**(struct natural alignment)
- **字段按对齐降序排列,padding 显式声明且 must be 0**(per D41 R1:jhyy 无 `packed`,紧凑布局不可表达,故一律自然对齐;凡有 padding 必须在 c-typedef 里显式写出 `_pad*` 字段,不允许隐式空洞 —— 否则两侧尺寸对不上)
- **no magic number / no version field**(versioning 走 spec 版本号,不走 wire)
- **payload_ptr 相对 event header base**(便于 memcpy + relocate)

## § 3 DebugEventKind enum(8 + 1 值)

```c
enum DebugEventKind : u32 {
    DebugEventKind_None            = 0,   // reserved / unset
    DebugEventKind_CapConstructed  = 1,   // Cap<T> 构造(per D12 8 条规则)
    DebugEventKind_CapGranted      = 2,   // grant() 调用
    DebugEventKind_CapRevoked      = 3,   // revoke() 调用
    DebugEventKind_ErrThrown       = 4,   // ErrChain 抛出
    DebugEventKind_ErrCaught       = 5,   // ErrChain 捕获(match arm)
    DebugEventKind_StateTransition = 6,   // KernelState 转换(§ 6)
    DebugEventKind_PanicReached    = 7,   // panic 触发
    DebugEventKind_UnsafeEntered   = 8,   // unsafe_cap block 进入(per D19)
    // ...
    DebugEventKind_Custom          = 0xFF, // 用户自定义
};
```

- **1-8**: 内核/编译器保留, kernel + jhyy-side 都可 emit
- **0xFF**: 用户 extension(per-sprint 3l std lib 决定细节)
- **0**: reserved / unset(用于 zero-init 区分)

## § 4 Confidence 三级标记(新)

### 4.1 设计动机

LLM agent 拿到 ProvenanceInfo,需要知道"哪些字段可信任 / 哪些是编译器推断 / 哪些是启发式"。当前 `v0.0.1-capability.md § 5.1` ProvenanceInfo 7 字段是平等,无 confidence 区分。

**三级标记** = 每个字段单独标 confidence。

### 4.2 Confidence enum

```c
enum Confidence : u8 {
    Confidence_HardFact         = 0,  // 编译期/运行期确定(ground truth)
    Confidence_CompilerInjected = 1,  // 编译器推断(call graph / type inference)
    Confidence_Heuristic        = 2,  // 启发式(syscall log 重放 / runtime probe)
};
```

### 4.3 ProvenanceInfo 字段 confidence 映射

| 字段 | 默认 confidence | 理由 |
|------|----------------|------|
| `constructed_at` | HardFact | SourceLoc 编译期确定 |
| `constructed_by` | CompilerInjected | call graph 推断,sema 阶段填 |
| `grant_chain` | HardFact (显式 grant) / Heuristic (从 syscall log 重放) | 显式 grant() 调用 = HardFact;从 cnode audit 反推 = Heuristic |
| `revoke_chain` | HardFact | revoke() 是 explicit syscall |
| `current_holder` | HardFact | kernel cnode 表跟踪 |
| `rights` | HardFact | kernel 分配时记录 |
| `created_at_ns` | HardFact | cap 构造时刻(ns 时间戳) |

### 4.4 实施位置(sema 阶段填)

```jhyy
// sema 阶段(实施时改 jhyy syntax,此处示意 fill_provenance 的 contract):
fn fill_provenance(p: &mut ProvenanceInfo, loc: SourceLoc) {
    p.constructed_at = loc;
    p.constructed_by = current_fn_id();  // sema 上下文
    p.constructed_at_confidence = Confidence_HardFact;
    p.constructed_by_confidence = Confidence_CompilerInjected;
    // ...
}
```

### 4.5 LLM agent 语义契约

- **HardFact**: trust as ground truth(可用于 security-critical decision)
- **CompilerInjected**: trust with caveat(可能错于边角 case)
- **Heuristic**: **必须展示启发式来源**, 不能用于 security decision,只能用于 hint / 探索

spec author 写时需要确保:
- Confidence enum 是公开 API(jhyy-side `enum Confidence`;jhyy 无 `pub` 可见性修饰符,且 3a-3n 全部 sprint 均未规划 —— per D41 review R3)
- ProvenanceInfo accessor 返回 `(value, confidence)` tuple(不是裸 value)
- sema 静态保证:凡 emit ProvenanceInfo 的代码路径,都必须填 confidence(否则编译警告)

## § 5 ErrChain ABI(替代 L2 placeholder)

### 5.1 当前 placeholder(`highlights-technical.md § 7`)

```
type Err<T> = struct {
    code: u32,
    prev: *Err,           // ← linked list 端
    trace: [CapId],       // ← stack trace
}
```

缺:具体 wire format / c-typedef / ProvenanceInfo 关联 / payload 布局。

### 5.2 C-typedef(本 spec 定义)

> 字段按对齐降序排列(同 § 2.2 原则)。**尺寸仍是 64B** —— 只改字段序,不改大小。

```c
typedef struct ErrChain {
    SourceLoc source_loc;     // 24 字节,错误抛出位置
    uint64_t  prev;           // ptr to prev ErrChain (0 = root)
    uint64_t  trace_off;      // ptr to [CapId; trace_len] (可空 = 0)
    uint64_t  context_off;    // ptr to [ProvenanceInfo; context_len] (可空 = 0)
    uint32_t  code;           // ErrCode enum (per v0.0.1-syscall-abi.md § 1.4)
    uint32_t  trace_len;      // stack trace 项数
    uint32_t  context_len;    // Cap<T>::provenance() 链长度
    uint32_t  _pad_end;       // 4 字节尾部 padding (must be 0)
} ErrChain;                  // sizeof = 64 字节, alignof = 8
```

| 字段 | 偏移 | 大小 | 用途 |
|------|------|------|------|
| source_loc | 0 | 24 | 错误抛出位置 |
| prev | 24 | 8 | linked list(0 = root) |
| trace_off | 32 | 8 | ptr to [CapId] 数组 |
| context_off | 40 | 8 | ptr to [ProvenanceInfo] 数组(可空 = 0) |
| code | 48 | 4 | ErrCode enum |
| trace_len | 52 | 4 | stack trace 项数 |
| context_len | 56 | 4 | ProvenanceInfo 链长度 |
| _pad_end | 60 | 4 | 尾部 padding (must 0) |

> 大小校验:末字段偏移 60 + 4 = **64**,三个 u64 指针字段(@24 / @32 / @40)全部 8-aligned,`source_loc` @0 亦满足其内嵌 u64 的对齐。
>
> **修正记录(2026-08-12, D41 review R2)**:初稿声称 64B 且"三个 u64 字段全部 8-aligned",但初稿偏移表给的 `prev@28` / `trace_off@40` 均未 8 对齐,`source_loc@4` 亦然(SourceLoc 含 u64 `reserved`,需 8 对齐);按初稿字段序真做自然对齐是 72B。重排后回到 64B。

### 5.3 jhyy-side 对应(替换 placeholder)

> **命名/语法修正(2026-08-12, D41 review R3)**:初稿写 `Err<T>`,但泛型是 **sprint 3i(v3.2+)** 才 ship,排在本 spec 的实现节点 sprint 3g(v3.1)**之后**;且 `T` 未在任何字段中使用。故去掉类型参数,并与 wire-format 同名为 `ErrChain`。
> 易混点:同期 `Cap<T>` 看似泛型,实为 phantom-type 特例(sema hardcoded + codegen skip `_phantom`,per D12 / `v3.x-capability-spec.md § 决策表 行 4`),**不走泛型机制**,不能据此认为 3g 时点有泛型。
> 3i 之后若需泛型化 `ErrChain<T>`,属 add-only 向后兼容改动,本 spec 不预留。

```rust
// jhyy-side(替换 v0.0.1-capability.md § 5 + highlights-technical.md § 7 placeholder)
type ErrChain = struct {
    source_loc: SourceLoc,           // 24B
    prev: *ErrChain,                 // linked list (null = root);NULL 结尾链 → 裸指针,per D40
    trace: [*]CapId,                 // stack trace;wire-format 有 trace_len → slice,per D40
    context: [*]ProvenanceInfo,      // Cap<T> provenance 链;wire-format 有 context_len → slice,per D40
    code: u32,                       // ErrCode
};
```

> `trace` / `context` 初稿写作 `[CapId]` / `[ProvenanceInfo]` —— `[T]` 无尺寸数组类型在 jhyy 中不存在,且 3a-3n 全部 sprint 均未规划。jhyy 只有 `[T; N]` 定长与 `[*]T` 切片(16B = ptr+len,per `jhyy-abi-v1.0.0.md § 2.3`)。

### 5.4 与 v0.0.1-capability.md § 5 关系

- ProvenanceInfo 是 jhyy-side struct(7 字段, per `v0.0.1-capability.md § 5.1`)
- ErrChain 通过 `context_off` 引用 ProvenanceInfo 数组(本 spec 新增)
- ProvenanceInfo 内部 `grant_chain / revoke_chain` 语义**不变**(仍是 NULL 结尾单向链),但 **jhyy-side 类型 2026-08-12 由 D40 修订为 `*ProvenanceInfo` 裸指针**(原 `[*]ProvenanceInfo` slice);wire-format 单 ptr 不动 → 两侧视图自此统一
- DAG 增强(§ 7)**是 ProvenanceInfo 内部字段加**, 不动 ErrChain layout

## § 6 KernelState + History ABI(新)

### 6.1 KernelState enum

```c
enum KernelState : u32 {
    KernelState_Init    = 1,  // 进程启动
    KernelState_Running = 2,  // 正常运行
    KernelState_Blocked = 3,  // syscall wait (channel / timer)
    KernelState_Panic   = 4,  // unrecoverable error
    KernelState_Halt    = 5,  // 进程结束 / 系统 halt
};
```

### 6.2 StateTransition

```c
typedef struct StateTransition {
    KernelState from;          // 4 字节
    KernelState to;            // 4 字节
    uint64_t    timestamp_ns;  // 8 字节
    SourceLoc   trigger_loc;   // 24 字节
    uint32_t    reason_code;   // ErrCode or KernelError
    uint32_t    reserved;      // 4 字节 padding for align
} StateTransition;            // 总 4+4+8+24+4+4 = 48 字节
```

### 6.3 KernelStateHistory(ring buffer)

```c
#define KERNEL_STATE_RING_SIZE 256  // default,可在 build 时调整

typedef struct KernelStateHistory {
    StateTransition ring_buf[KERNEL_STATE_RING_SIZE];  // 256 × 48 = 12288 字节
    uint32_t head;              // write pointer (mod KERNEL_STATE_RING_SIZE)
    uint32_t tail;              // read pointer (mod KERNEL_STATE_RING_SIZE)
    uint32_t overflow_count;    // overflow events since boot
    uint32_t reserved;          // padding
} KernelStateHistory;          // 总 ~12304 字节
```

### 6.4 行为

- **进程每次 state transition 写一条**: `head = (head + 1) % N`,写入 ring_buf[head]
- **debug build 默认 N=256**, release build strip(整段不 emit)
- **overflow**: 当 tail == head 时仍 write → 丢弃旧条目 + overflow_count++
- **与 DebugEvent 联动**: StateTransition 触发 `DebugEventKind_StateTransition` 事件(`event_type=6`),DebugEvent payload 字段携带:
  - `payload_ptr` → 指向外部分配的 StateTransition(46-48B,per § 6.2)
  - `payload_len = sizeof(StateTransition) = 48`
  - `source_loc` → 触发位置(`trigger_loc` 跟 payload 内的 `trigger_loc` 字段冗余存,跟 payload 内字段语义独立——DebugEvent.source_loc 用于"emit 该 event 的源码位置",payload.trigger_loc 用于"state transition 发生位置")

### 6.5 LLM agent 拉取

- debug build 暴露 syscall `debug_query_kernel_state(pid) -> *KernelStateHistory`
- LLM agent 解析 ring buffer,按 timestamp_ns 排序,重建 state history timeline
- ring buffer 满后,FIFO 顺序展示(head/tail 处理)

## § 7 ProvenanceInfo 增强: DAG vs list(新)

### 7.1 当前(`v0.0.1-capability.md § 5.1`,D14 锁)

> ⚠️ 以下为**修订前快照**(存档用)。`grant_chain` / `revoke_chain` 的类型已于 2026-08-12 由 **D40** 改为 `*ProvenanceInfo` —— 现行定义见 § 7.3。

```rust
type ProvenanceInfo = struct {
    constructed_at: SourceLoc,
    constructed_by: FnId,
    grant_chain: [*]ProvenanceInfo,     // ← 单向 list
    revoke_chain: [*]ProvenanceInfo,
    current_holder: ProcessId,
    rights: u16,
    created_at_ns: u64,
}
```

### 7.2 不足:multiparent derive 表达不够

场景:`c1 = kernel_alloc(); c2 = c1.subset(...); c3 = c2.derive(...)`,但同时 `c4 = c1.subset(...)`(另一个 subset)。
当前 list: `c3.grant_chain` 只能追到 c2,c2.grant_chain 追到 c1;但 c4 跟 c3 在 c1 处分叉,list 表达不了这个分叉点。

### 7.3 DAG 增强(add-only, 向后兼容)

加字段(不动现有 7 字段):

```rust
type ProvenanceInfo = struct {
    // 现有 7 字段 (per v0.0.1-capability.md § 5.1, D14 锁;chain 两字段类型 2026-08-12 由 D40 修订)
    constructed_at: SourceLoc,
    constructed_by: FnId,
    grant_chain: *ProvenanceInfo,      // D40: NULL 结尾单向链 → 裸指针(原 [*]ProvenanceInfo slice)
    revoke_chain: *ProvenanceInfo,     // 同上
    current_holder: ProcessId,
    rights: u16,
    created_at_ns: u64,

    // 新增 (本 spec): DAG 节点信息
    parents: [u32; 8],     // parent ProvenanceInfo id (multiparent derive)
    children: [u32; 8],    // child ProvenanceInfo id (forward lookup)
    parents_len: u8,       // actual parents count (max 8)
    children_len: u8,      // actual children count (max 8)
    // K=8 default, fixed-size 数组 (避免 heap alloc)
}
```

> **D40 修订(2026-08-12)**:`grant_chain` / `revoke_chain` 原为 `[*]ProvenanceInfo`(jhyy slice,16B = ptr+len),与 wire-format 的单 ptr(8B)构成两种视图。现统一为裸指针 —— 详见 § 7.5。

**大小(D40 修订后两侧一致,不再是"估算")**:

| 区段 | 字段 | 偏移 | 字节 |
|------|------|------|------|
| 原 7 字段 | `constructed_at` SourceLoc | @0 | 24 |
| | `constructed_by` FnId(u32) | @24 | 4 |
| | *(u64 对齐 padding)* | @28 | 4 |
| | `grant_chain` `*ProvenanceInfo` | @32 | 8 |
| | `revoke_chain` `*ProvenanceInfo` | @40 | 8 |
| | `current_holder` ProcessId(u32) | @48 | 4 |
| | `rights` u16 | @52 | 2 |
| | *(u64 对齐 padding)* | @54 | 2 |
| | `created_at_ns` u64 | @56 | 8 |
| **小计(原 7 字段)** | | | **64** |
| DAG 新增 | `parents[8]` | @64 | 32 |
| | `children[8]` | @96 | 32 |
| | `parents_len` / `children_len` | @128 | 2 |
| | *(尾部对齐 padding)* | @130 | 6 |
| **总计** | | | **136** |

> **与 wire-format 完全一致**:§ 7.5 c-typedef 亦为 136B。这正是 D40 的核心收益 —— 改单 ptr 后两侧尺寸自动对齐,不再需要"jhyy 侧 / wire 侧各算一遍"。
>
> **修正记录**:初稿两处算错 —— (a) "+ 8×4 + 1 + 1 = 34B" 只算了 parents 或 children 之一,正确是 32+32+2 = 66B;(b) "总 jhyy-side ~146B" 是 slice 假设(2×16B)下的产物,D40 改单 ptr 后作废。

### 7.4 为什么 K=8

- OS 端实际 multiparent derive 深度罕见 > 3(per v0.0.1-capability.md § 8 放弃 propagation)
- K=8 = 32B, 跟 SourceLoc 24B 同数量级,不算大
- fixed-size 数组 = no heap alloc = 编译期确定,符合"可行且简单"
- sprint 3g 实施时如果 OS 团队遇到 K=8 不够,再放宽(forward compatible)

### 7.5 wire format

对应 c-typedef(在 § 5.3 ErrChain.context_off 引用处):

```c
typedef struct ProvenanceInfo {
    SourceLoc  constructed_at;      // 24  @0   (align 8)
    uint32_t   constructed_by;      // 4   @24  (FnId)
    uint32_t   _pad_chain;          // 4   @28  (u64 alignment for chain ptrs)
    uint64_t   grant_chain_off;     // 8   @32  (chain 头 ptr;对应 jhyy-side *ProvenanceInfo,per D40;NULL = root)
    uint64_t   revoke_chain_off;    // 8   @40
    uint32_t   current_holder;      // 4   @48  (ProcessId)
    uint16_t   rights;              // 2   @52
    uint16_t   _pad_ts;             // 2   @54  (u64 alignment for created_at_ns)
    uint64_t   created_at_ns;       // 8   @56

    // DAG extension (sprint 3g.5)
    uint32_t   parents[8];          // 32  @64  (align 4)
    uint32_t   children[8];         // 32  @96
    uint8_t    parents_len;         // 1   @128
    uint8_t    children_len;        // 1   @129
    uint16_t   _pad_end;            // 2   @130 (alignment pad)
    // tail-align to 8: implicit 4B pad → 136
} ProvenanceInfo;                  // sizeof = 136 字节, alignof = 8
```

**D40 表达规则(2026-08-12 锁,修订 D14 字段类型部分)**:

初稿这里 jhyy 侧是 slice(16B ptr+len)、wire-format 是单 ptr(8B),`len` 从链尾 NULL 隐式推导 —— 两种视图并存,序列化有损,且 `len` 语义从未定义(没人填、没人信)。现落一条**可推广规则**取代逐字段特判:

> **wire-format 有显式 `*_len` 字段 → jhyy 侧用 `[*]T` slice;wire-format 是 NULL 结尾单向链 → jhyy 侧用 `*T` 裸指针。**

全 spec 套用结果:

| 字段 | wire-format | 判定 | jhyy-side |
|------|------------|------|-----------|
| `ProvenanceInfo.grant_chain` / `revoke_chain` | `uint64_t`,NULL=root,无 len | 链 | `*ProvenanceInfo`(**D40 改**)|
| `ErrChain.prev` | `uint64_t`,0=root,无 len | 链 | `*ErrChain`(已正确)|
| `ErrChain.trace` | `trace_off` + `trace_len` | 数组 | `[*]CapId`(**R3 改**)|
| `ErrChain.context` | `context_off` + `context_len` | 数组 | `[*]ProvenanceInfo`(**R3 改**)|

**理由**:grant chain 派生自 cnode 树,本就是 linked list(per `v0.0.1-capability.md § 5.4` "单向 list" 措辞);初稿自己写的也是"取 slice.data 作为 next 指针",即 `len` 从未参与语义。且 § 7.2 已承认 list 表达不了 multiparent 分叉 —— 真实结构由新增 DAG `parents[8]` / `children[8]` 承载,slice 语义纯属负担。

**收益**:jhyy 侧与 wire-format 均为 **136B**(见 § 7.3 尺寸表),两侧视图统一,codegen 直译,无 `len` 同步问题。

> D14 主体决策(provenance 是 OS 独有 debug / 不进 std / debug build side table / `Cap::provenance()` 接口)**不变**;D40 只修订 `v0.0.1-capability.md § 5.1` 的字段类型。
>
> **136B 已定**(D40 收益:两侧一致);sprint 3g.5 phantom 实施时如 DAG K 值调整,按 § 7.4 forward-compatible 路径再议。

## § 8 CodeGraph 定位(联合自省)

### 8.1 CodeGraph MCP(现状)

- 静态代码图谱(call graph + type graph + import graph)
- **源码视角**: 编译前/编译期分析
- 在 `~/.claude.json` `mcpServers.codegraph` 注册(per `~/.claude.json` settings)
- **不替代**: CodeGraph 是已有工具,本 spec 不重写

### 8.2 Debug ABI(本 spec 新增)

- **编译期 metadata** (`--debug-info` 选项拉): DebugEventKind enum + ProvenanceInfo struct layout + ErrChain 格式 — 给 CodeGraph 喂数据
- **运行期 ring buffer** (introspection syscall): KernelStateHistory + 实时 emit 的 DebugEvent
- **联合自省图谱**: 静态 + 动态双视角

### 8.3 互补关系表

| 视角 | CodeGraph | Debug ABI |
|------|-----------|-----------|
| 静态(call/type graph) | ✅ 强项 | ⚠️ 仅 metadata(--debug-info) |
| 动态(runtime state) | ❌ 无 | ✅ KernelStateHistory ring buffer |
| 跨进程(cap 流转) | ❌ 无 | ✅ DebugEventKind::CapGranted + provenance |
| LLM agent 拉取 | 编译时一次性 | 持续流(streaming) |
| 字节大小 | 几百 KB 到几 MB | debug build + side table,可 strip |

### 8.4 不替代关系

- CodeGraph = 源码视角; Debug ABI = 运行期视角
- LLM agent 用 CodeGraph **理解代码结构** (call graph, type hierarchy)
- LLM agent 用 Debug ABI **诊断运行时问题** (state transition, cap provenance, error chain)
- 两者组合 = 联合自省(joint introspection)

### 8.5 CodeGraph 如何消费 Debug ABI

- 编译期: `--debug-info` 输出 JSON/二进制 metadata, CodeGraph 摄入(call graph + provenance 节点关联)
- 运行期: DebugEvent 流(ring buffer 或 introspection syscall) → CodeGraph 实时注解 call graph 边(grant/revoke event 染边色)
